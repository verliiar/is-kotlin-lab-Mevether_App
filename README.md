# **Mevether**

**Mevether** — система совместного управления проектами и задачами с механизмом синхронизации данных и разрешения конфликтов при параллельном редактировании.

Проект предназначен для организации командной работы, распределения задач между участниками и отслеживания их выполнения. Его ключевая особенность — возможность корректно обрабатывать ситуации, когда несколько пользователей одновременно изменяют одну и ту же задачу.

## **Идея проекта**

При совместной работе над проектом несколько участников могут независимо редактировать задачи, изменять их описание, статус или другие параметры. Если изменения происходят одновременно, возникает риск потери данных: правки одного пользователя могут перезаписать результаты работы другого.

**Основная цель Mevether — обеспечить согласованность данных при совместном редактировании и предотвратить незаметную потерю пользовательских изменений.**

Для этого система отслеживает версии задач, фиксирует историю изменений и предоставляет несколько способов разрешения конфликтов.

## **Функциональные возможности**

### **Управление проектами**

Пользователи могут создавать проекты для организации совместной работы и объединять в них связанные задачи.

В рамках проекта предусмотрены:

- Создание и управление проектами.
- Добавление участников команды.
- Распределение ролей и прав доступа.
- Организация задач внутри проекта.

### **Управление задачами**

Каждый проект содержит задачи, над которыми могут работать его участники.

Система позволяет:

- Создавать новые задачи.
- Просматривать информацию о существующих задачах.
- Редактировать название, описание и другие параметры задач.
- Изменять статус выполнения.
- Отслеживать историю внесённых изменений.

### **Совместное редактирование**

Несколько участников могут работать с одними и теми же задачами.

При сохранении изменений система учитывает версию задачи, на основе которой пользователь выполнял редактирование.

Если задача была изменена другим участником, система обнаруживает расхождение версий и обрабатывает его в соответствии с выбранной стратегией синхронизации.

Это позволяет избежать ситуаций, когда изменения одного пользователя незаметно заменяют изменения другого.

### **Синхронизация и разрешение конфликтов**

**Центральная функциональность Mevether — обработка конкурирующих изменений.**

Система поддерживает три стратегии разрешения конфликтов:

**1. Last Write Wins (LWW)**

При возникновении конфликта приоритет получает последнее изменение в соответствии с правилами системы.

Стратегия подходит для ситуаций, когда важнее автоматически принять итоговое состояние задачи, чем сохранять каждую конкурирующую правку.

**2. Smart Merge**

Система пытается автоматически объединить изменения нескольких пользователей.

Если участники изменили разные части текста, их правки могут быть объединены без ручного вмешательства.

Если изменения несовместимы, система фиксирует конфликт для дальнейшего разрешения.

**3. Admin Approval**

При обнаружении конфликта система сохраняет конкурирующие варианты изменений и передаёт решение пользователю с соответствующими правами.

Ответственный участник может рассмотреть предложенные варианты и выбрать итоговое состояние задачи.

Такой подход позволяет контролировать изменения в ситуациях, когда автоматическое разрешение конфликта нежелательно.

### **История изменений**

Mevether сохраняет информацию об изменениях задач, позволяя отслеживать их развитие в процессе командной работы.

История изменений помогает определить, какие правки были внесены, и обеспечивает прозрачность совместного редактирования.

### **Пользователи и права доступа**

Система предусматривает регистрацию и авторизацию пользователей, участие в совместных проектах и разграничение доступных действий в зависимости от роли участника.

Это позволяет организовать командную работу и ограничить изменение данных пользователями без соответствующих полномочий.

## **Пример использования**

Два участника команды открывают одну задачу с описанием:

Подготовить документацию проекта.

Первый пользователь дополняет описание требованиями к содержанию документации.

Второй пользователь в это же время добавляет информацию о сроках подготовки.

Оба участника сохраняют свои изменения.

В обычной системе без контроля версий существует риск, что последнее сохранение перезапишет предыдущие правки.

В Mevether система обнаруживает, что оба пользователя редактировали одну версию задачи, и применяет выбранную стратегию разрешения конфликта.

Например, при использовании **Smart Merge** совместимые изменения могут быть автоматически объединены, а при использовании **Admin Approval** решение будет передано ответственному участнику.

## **Цель проекта**

Mevether разрабатывается как учебный проект, посвящённый организации совместной работы с общими данными.

Основная задача — реализовать систему управления проектами и задачами, в которой особое внимание уделяется **синхронизации изменений, контролю версий, обнаружению конфликтов и обеспечению согласованности данных при параллельном редактировании**.
